# 自媒体视频制作

先判断输入是**已有视频**还是**从脚本生成**。已有视频以原画面、原声和校对后的转写为内容依据；脚本生成的视频以分镜和旁白文本为依据。沿用用户已确认的标题、内容、参考图和排版要求，不因套模板而改掉它们。用户只要方案时交付方案；要求成片时继续做到可播放文件和画面验收。

## 先检查素材

用 `ffprobe` 确认画幅、帧率、时长和音轨，试听开头、中段、结尾，抽帧看 UI、人物、字幕安全区及平台遮挡区。区分可用人声、仅背景音乐、无声素材；记录哪些区域不能覆盖。不要默认把横屏录屏裁成竖屏，优先保留用户需要展示的原始内容与清晰度。

## 已有口播或录屏

1. **保留原声**。已有可用讲话声时不生成 TTS，也不把新配音叠在原声上。音乐或环境声是否保留按内容判断。只有没有可用讲述、成片又确实需要旁白时，才按用户要求或已确定的脚本选择 TTS。
2. **先校对，再剪辑**。转写人声并校对专有名词、技术名词和语义；结合音频活动、词级时间戳及画面变化提出剪辑点。优先去掉明显的气口、空等、卡顿和重复，保留自然呼吸及句首尾辅音。先检查剪辑计划，再导出；不要仅凭音量阈值盲切。保留源时间到成片时间的映射，让字幕、章节和动效使用同一条剪后时间线。
3. **双语字幕**。按剪后的讲话声对齐中文和自然、简短的英文。录屏默认采用本次确认过的视觉方向：画面下部居中的黄色中英两行、中文较大、细暗描边、透明背景，**不加黑色字幕底板**。具体位置和字号按用户参考图、画幅与内容留白调整；不压住人脸、关键按钮或演示焦点。提供独立 SRT，烧录版与 SRT 同步。
4. **顶部进度条**。进度条处于原视频画面之外的外扩顶栏，紧贴原视频的上方视觉边界；线条细、轨道透明或半透明，按剪后总时长连续推进。顶栏可放简短章节名/编号，但不得挤占或覆盖原录屏顶部的菜单、标题栏等信息。参考图若明确了线条在顶栏上沿或贴原视频边界，按参考图执行。不要从其他技能继承底部导航或黑色大面积底板。
5. **Remotion 动效插图**。根据正在讲的内容制作少量有信息量的插图或标注动效，例如提示词到原型再到应用的递进、局部高亮、箭头、对比或画中画。它们可以穿插在画面留白、外扩区域、镜间或短暂说明镜头；**不固定在顶部**。先标出原画面重要区域，动效不能挡住演示、人脸、字幕或进度条。为每个动效记录入场、变化和退场时间，按原声语义渲染进最终 MP4。

可复用 `video-bilingual-degap-navigation` 的转写、VAD 和剪辑计划能力；其固定白字幕、黑色底部导航样式不作为本技能的成片样式。具体合成与版式检查见 [references/remotion-pipeline.md](references/remotion-pipeline.md)。

## 从脚本生成

按 [references/shot-list-template.md](references/shot-list-template.md) 写逐镜脚本：每镜的结论、讲述、画面、动效位置、起止时点和安全区。若已有可用旁白，直接采用；没有旁白且成片需要讲述时，再使用 `dashscope-custom-voice-tts` 或用户指定方式。实测音频时长写回时间线。字幕从定稿讲述文本派生；不必重新 ASR。默认沿用黄色无底板的双语字幕方向，具体位置服从分镜和参考图。动效由镜头内容与画面构图决定，不强制每镜都有顶部 HUD。

封面只在用户要求时制作，使用用户指定的模型、风格和文字；先确认封面钩子与视频内容相符，再检查文字是否清楚、人物或产品是否失真。示例做法见 [references/worked-example.md](references/worked-example.md)。

## 文案、归档与抖音发布

当用户要求发布或自动发布时，每条成片都要同时产出：

- 一个与视频内容一致的标题；
- 一段可直接粘贴到抖音的正文；
- 3–5 个相关标签；
- 成片、封面、文案、SRT、时间线和 manifest（有则带上）的同批归档。

文案只能使用视频实际讲到或画面实际展示的信息，不虚构没有出现的功能、数据或结论。用 `scripts/archive_media.py` 在 `/Users/pengfanao/Desktop/剪辑素材-视频/自媒体` 下创建唯一目录；归档脚本会复制文件、写入 `caption.md`、`metadata.json`、`archive-manifest.json` 和 `upload-state.json`，并记录 SHA-256。归档完成后才进入上传步骤，上传失败不得删除或覆盖归档。

抖音上传只允许复用已有登录会话：

1. 默认使用用户已经打开并登录的 Google Chrome 窗口，在同一窗口新建一个抖音标签页；不得启动新的 Chrome 进程、浏览器窗口、用户配置或账号登录流程。
2. 如果当前环境提供 Chrome CDP，可使用 `scripts/upload_douyin.mjs` 的 `chrome-cdp` 模式；如果没有 CDP，使用浏览器插件/现有窗口控制，通过 DOM、无障碍控件和系统文件选择器完成上传。CDP 不是默认前置条件。
3. 只有已有抖音 Mac App 自己暴露 Electron CDP 时才尝试 `douyin-app-cdp`。不要自动扫码、登录、接管其他账号或关闭用户的浏览器/App；不得用截图坐标作为主要上传方法。
4. 默认只上传并停留在草稿状态，不点击“发布”；回查上传完成或草稿提示后报告 `draft_ready`，未确认时报告 `draft_unverified`。只有用户明确要求发布并显式使用发布模式时，才点击发布并回查成功、审核中或已发布状态；异常报告 `failed`。

必要的 CDP 配置、页面复用规则和命令示例见 [references/douyin-publish.md](references/douyin-publish.md)。

## 预览与验收

- 动工前明确画幅及画面安全区；渲染前先出有字幕、有进度条、有动效的代表帧。用户要求截图确认时，先交截图再继续整片。
- 检查开头、中段、章节切换、结尾和动效最密集的帧：顶栏没有压住原视频，黄色字幕没有黑底且可读，动效不遮重点，进度随时间推进。对每个动效至少对比其前后两帧，并在最终 MP4 中确认它确实出现和变化。
- 用 `scripts/qa_video.sh <mp4> [关键帧编号…]` 核对规格、完整解码、音量、抽帧和 SHA-256；再实际试听剪辑点，确认没有吞字、音画错位或双重配音。保留原始素材，不覆盖源文件。

交付成片 MP4、双语 SRT、必要的时间线/工程、封面、`caption.md` 和归档目录。上传或发布只在用户明确请求时执行，并以平台上的作品状态核实结果；发布失败时仍交付归档目录和具体失败原因。
